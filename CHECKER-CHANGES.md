## Changes

### check_release1.py

**K1. Pair classification by explicit topology.** Previously, how an atom pair was classified (central–ligand, cis, trans, chain neighbour) depended on case names (`'allyl cation pi'`), a preset id (`'sixH_lecture'`) and a list of central elements. The six-H trans test also used unnormalised positions, so it was right only because R ≈ 1 Å. Now each fixture passes `topology` (`central`, `chain`, `cistrans` or `all`), and cis/trans uses normalised positions.
*Effect:* no change in enabled edges for any current fixture. Confirmed by the smoke run below, which reproduces every Appendix B energy.

**K2. Irrep labels asserted against CONVENTIONS Appendix B.** Previously, labels for water, H2, H3, allyl and the ligand-only sets were checked only against `evidence/reference_spectra.json`, which was itself generated by this script. The C2v b1/b2 swap, the error the spec names, could have passed that way. Every fixture's full irrep sequence is now asserted against Appendix B. Two extra checks:
- the out-of-plane O px is the B1 nonbonding level in both water presets;
- the allyl cation HOMO is B1 and its LUMO is A2 (spec F2.10).

The label spellings (`A1'`, `E'`, `A2''`, `Ag`, `B1u`, …) were confirmed against MolSym 1.3.1 output after `generate_groups.norm`.

**K3. Additional missing-channel test on a pair that exists.** The original N–N test is kept.

*Patch 1 version (withdrawn):* a B–S `pp_pi` lookup, on the assumption that no B–S row existed. The real `params/pairs.csv` has full B–S rows (lines 29–32), so that lookup succeeds and the patch-1 test fails with `missing B-S pair row … silently accepted`. The assumption was mine and wrong; it was found when the real `params/` arrived.

*Patch 3 version:* an `O,H,pp_pi` lookup, expecting `ValueError` or `LookupError`. O–H has `ss_sigma` and `sp_sigma` rows but no `pp_pi` row; a precondition assert reads `pairs.csv` and checks exactly that, so the test cannot silently become vacuous if rows are added. This exercises a missing channel for an existing pair, which the N–N test (no rows at all) does not.
*Correction (patch 2):* patch 1 said the N–N test only showed that a missing *element* raises. That was wrong. `Parameters.get` never reads the on-site table, so N–N already went through the missing-pair-row path. K3 adds a case with known elements; it doesn't close a gap.

**K4. Level descriptors written to `checks/crystod_cases.json`.** Each level gets `{character, dominant_fragment, bond_energy_eV}`:
- `character` is the sign of 2Σ c_i c_j H_ij over central–ligand pairs, or over all inter-atomic pairs when there is no central atom, averaged over the degenerate set. |x| ≤ 1e−6 eV counts as nonbonding.
- `dominant_fragment` is `central` when the central-atom weight is above 0.5, `ligand` otherwise, and `ligand_only` when there is no central atom.

Both are unchanged by any rotation within a degenerate set. The rule text is stored in each case as `descriptor_rule`. Nothing is added to `release1_energies.csv`, `release1_validation.json` or the `reference_spectra.json` comparison.

### compare_crystod.py

**K5. Explicit failure messages.** Bare `assert`s are replaced by `require(cond, msg)`, which raises a `ValueError` naming the case and the missing or invalid field. Asserts disappear under `python -O`, and when they fire they put an empty `AssertionError: ` into the manifest.

**K6. Linear point group from geometry.** Previously the full point group was `Dinfh` only when the case was named `H2`. Collinear geometries now give `Dinfh` if centrosymmetric with matching elements, and `Cinfv` otherwise.

**K7. Checker levels outside the contract basis are excluded before counting.** The adapter must report `contract_basis_weight` in [0, 1] for each level. Levels below 0.5 are excluded and listed in `excluded_outside_contract_basis`. Contract irreps the checker has no level for are listed in `contract_irreps_not_shared`. Without this, an all-valence F basis in SF6 would always fail the counts.

**K8. Within-irrep order compared through descriptors.** Each level must carry a `descriptor` computed by the K4 rule from the checker's own eigenvectors. The sequence of `(character, dominant_fragment)` within each irrep is compared. Previously the check was on adapter-assigned `canonical_level_id`s, which an adapter can only number from energy order, so it passed by construction. The ids are still recorded as evidence.

**K9. Adapter failures report exit code and stderr** instead of a bare `CalledProcessError`.

**K11 (patch 2). Order differences no longer fail the build.** Spec §12 says a qualitative order mismatch "goes to the owner rather than failing automatically, because the models differ", while label and degeneracy mismatches block release. Both v1.2 and patch 1 returned `DISAGREEMENT_ORACLES_PREVAIL` (exit 1) for any order difference. Now:

| Per-case status | Meaning |
|---|---|
| `PASS` | Everything matches |
| `DISAGREEMENT_ORACLES_PREVAIL` | Point group, shared-basis count or degeneracy mismatch. Blocking. |
| `ORDER_REVIEW_FOR_OWNER` | Blocking checks pass but descriptor order differs. Not blocking. |

Overall: any disagreement gives exit 1. Otherwise any missing case gives `BLOCKED` (exit 2). Otherwise order reviews give `PASS_WITH_ORDER_REVIEW` (exit 0), with the affected cases listed in `order_review_cases`. This also softens a weakness of K4: `dominant_fragment` can flip between models for levels near 50/50, and that now leads to review, not failure.

The report gains a `comparison_rules` block, and `allowed` now reads `within_irrep_descriptor_order`.

### check_support.py

**K10 (patch 2). Mock protocol tests updated for K5–K8 and K11.** The v1.2 mocks lacked descriptors and weights, so after patch 1 they would have stopped with a K5 `ValueError`. They also caught only `AssertionError`.

*Correction (patch 2):* patch 1 said these tests were in `build_checks.py`. They are in `check_support.py`.

Mocks now include a level outside the contract basis, which must be excluded while the case still passes. Mutations:

| Class | Mutations | Expected result |
|---|---|---|
| Blocking | point group, degeneracy, label map, extra level moved inside the contract basis, missing weight, missing descriptor | `DISAGREEMENT_ORACLES_PREVAIL` or a named `ValueError` |
| Order | energy swap, descriptor swap | `ORDER_REVIEW_FOR_OWNER` |

The keys written to `checks/crystod_protocol_tests.json` list these classes.

## Adapter protocol (for whoever writes the real adapter)

Each entry in `levels` needs `irrep`, `energy`, `multiplicity`, `canonical_level_id`, plus two more fields:
- `contract_basis_weight`: the fraction of the level on functions that correspond to the contract basis. With extended Hückel's nonorthogonal basis, state whether this is a Mulliken or Löwdin weight in `level_identity_evidence`.
- `descriptor`: `{character, dominant_fragment}`, computed by the K4 rule from the checker's own eigenvectors and Hamiltonian.

**K12 (patch 4). Host Python version no longer written into a committed check file.** `checks/lock_validation.json` recorded `test_runtime_python` (3.12.8 in v1.2). `make check-baseline` byte-compares the regenerated `checks/` against the committed one, so the baseline could pass only on a 3.12.8 host — not on this machine's 3.12.3, and not on the production pin 3.12.7. The field is replaced by `runtime_python: "printed at run time, not committed"`, and `check_support.py` prints the interpreter version to stdout instead. The lock file's hashes, not this field, are what pin the environment.
*Evidence for the change:* regenerating the whole bundle under 3.12.8 and under 3.12.3 gave identical output in every file except this one field.

**K13 (patch 5). Personal name removed from the public repository.** At the repository owner's request, every occurrence of the CONVENTIONS change authority's personal name was replaced by a role term, in all files including the uploaded v1.2 documents (`CONVENTIONS.md`, `README.md`, `evidence/CONVENTIONS-v1.2-TODO.md`, `params/decision_defaults.json`, the spec) and the checker scripts and outputs. Wording: "the owner" / "the project owner"; this file uses "the CONVENTIONS owner" where it must be told apart from the repository owner. Identifiers changed: status `ORDER_REVIEW_FOR_OWNER` (was the name in capitals) and decision status `default_pending_owner_approval`. No numerical content, rule or check changed.

*History rewrite (patch 5, owner-approved):* the branch history was then rewritten with `git filter-repo` so that no commit's files or messages contain the name, and force-pushed; every commit ID changed, and the IDs quoted in this file were updated. Consequence for provenance: the "v1.2 SHA-256" column above records the bytes as originally uploaded. For `scripts/compare_crystod.py` and `checks/crystod_manifest.json`, whose originals contained the name, the redacted copies now in git history no longer hash to those values; all other v1.2 originals in history are unchanged byte-for-byte. The unredacted originals are not in the public repository.
