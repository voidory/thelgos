## Changes

### check_release1.py

**K1. Pair classification by explicit topology.** Previously, how an atom pair was classified (central–ligand, cis, trans, chain neighbour) depended on case names (`'allyl cation pi'`), a preset id (`'sixH_lecture'`) and a list of central elements. The six-H trans test also used unnormalised positions, so it was right only because R ≈ 1 Å. Now each fixture passes `topology` (`central`, `chain`, `cistrans` or `all`), and cis/trans uses normalised positions.
*Intended effect:* no change in enabled edges for any current fixture. Each fixture's pairs map to the same type strings as before.

**K2. Irrep labels asserted against CONVENTIONS Appendix B.** Previously, labels for water, H2, H3, allyl and the ligand-only sets were checked only against `evidence/reference_spectra.json`, which was itself generated by this script. The C2v b1/b2 swap, the error the spec names, could have passed that way. Every fixture's full irrep sequence is now asserted against Appendix B. Two extra checks:
- the out-of-plane O px is the B1 nonbonding level in both water presets;
- the allyl cation HOMO is B1 and its LUMO is A2 (spec F2.10).

*Assumption to verify:* the label spellings `A1'`, `E'`, `A2''`, `Ag`, `B1u` follow the style the script already uses (`"A2''"`). If `groups/*.json` spells them differently, K2 fails loudly instead of passing quietly.

**K3. Missing-pair test uses known elements.** The existing test `P.get('N','N',…)` raises because nitrogen is missing altogether. It never showed that a missing pair row for elements that are present raises an error. The patch adds a B–S `pp_pi` lookup, first confirming both elements have on-sites, and expects `ValueError` or `LookupError`. The nitrogen test is kept.

**K4. Level descriptors written to `checks/crystod_cases.json`.** Each level gets `{character, dominant_fragment, bond_energy_eV}`:
- `character` is the sign of 2Σ c_i c_j H_ij over central–ligand pairs, or over all inter-atomic pairs when there is no central atom, averaged over the degenerate set. |x| ≤ 1e−6 eV counts as nonbonding.
- `dominant_fragment` is `central` when the central-atom weight is above 0.5, `ligand` otherwise, and `ligand_only` when there is no central atom.

Both are unchanged by any rotation within a degenerate set. The rule text is stored in each case as `descriptor_rule`. K8 uses these descriptors. Nothing is added to `release1_energies.csv`, `release1_validation.json` or the `reference_spectra.json` comparison.

### compare_crystod.py

**K5. Explicit failure messages.** Bare `assert`s are replaced by `require(cond, msg)`, which raises a `ValueError` naming the case and the missing or invalid field. Asserts disappear under `python -O`, and when they fire they put an empty `AssertionError: ` into the manifest.

**K6. Linear point group from geometry.** Previously the full point group was `Dinfh` only when the case was named `H2`, so the coming B2, C2, O2, F2 and CO fixtures would have expected `D2h`/`C2v` as their full group. Collinear geometries now give `Dinfh` if centrosymmetric with matching elements, and `Cinfv` otherwise.

**K7. Checker levels outside the contract basis are excluded before counting.** Previously, extended Hückel over all F valence orbitals in SF6 would always fail the per-irrep count and degeneracy checks. The spec says such extra levels are expected. The adapter must now report `contract_basis_weight` in [0, 1] for each level. Levels below 0.5 are excluded and listed in `excluded_outside_contract_basis`. Contract irreps the checker has no level for are listed in `contract_irreps_not_shared`.

**K8. Within-irrep order compared through descriptors.** Previously, order passed when the adapter's `canonical_level_id`s, sorted by checker energy, read `label:1, label:2, …`. An adapter can only assign that numbering from energy order, so the check passed by construction. Now each level must carry a `descriptor` computed from its own eigenvector by the K4 rule. The check compares the sequence of `(character, dominant_fragment)` within each irrep. `canonical_level_id`s are still recorded as evidence but no longer decide PASS.

**K9. Adapter failures report exit code and stderr** instead of a bare `CalledProcessError`.

The report gains a `comparison_rules` block, and `allowed` now reads `within_irrep_descriptor_order`.

## Adapter protocol changes (for whoever writes the real adapter)

Each entry in `levels` now needs two more fields besides `irrep`, `energy`, `multiplicity` and `canonical_level_id`:
- `contract_basis_weight`: the fraction of the level on functions that correspond to the contract basis. With extended Hückel's nonorthogonal basis, state whether this is a Mulliken or Löwdin weight in `level_identity_evidence`.
- `descriptor`: `{character, dominant_fragment}`, computed by the K4 rule from the checker's own eigenvectors and Hamiltonian.

## Verification status

- Both scripts compile under CPython 3.13.
- **K5–K8:** exercised with mock inputs only (an SF6-like case):
  - a superset basis with an F-2s-dominated a1g level and a t2g set → PASS, with both excluded;
  - swapped a1g characters → `DISAGREEMENT_ORACLES_PREVAIL`;
