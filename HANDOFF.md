## 1. What this is

A browser app for teaching molecular-orbital diagrams with the LGO (ligand group orbital) method of a university module. Most of the course cases are lecture cases, though some come from its Week 7 tutorial.

- **Model.** Orthogonal tight-binding (Hückel-like, no overlap):
  - on-site energies from Miessler, Fischer & Tarr's teaching table;
  - couplings from Harrison's distance law, V = η·7.62/d² (η ssσ −1.40, spσ +1.84, ppσ +3.24, ppπ −0.81), with every H-containing coupling scaled by 0.6.
- **Architecture.**
  - The engine is Python (NumPy) and runs in the browser through Pyodide 0.27.7 in a Web Worker.
  - The front end is vanilla JS, HTML, CSS and SVG, with no build step and no backend.
  - The engine computes everything. The JS only draws what the engine returns.
- **Ground truth.** `CONVENTIONS.md` is the frozen contract: geometries, signs, parameters, analytic oracles, regression energies. An independent checker (`scripts/`) re-derives every fixture from closed-form blocks and compares byte for byte.

## 2. Working rules: follow these

The **owner** is the project owner. The repository is **public**: refer to the owner by role ("the owner"), never by name.

- **Record decisions.** Every design decision goes in `DECISIONS.md`. Owner decisions are marked "owner"; choices delegated to the agent are marked "delegated"; state the reasons.
- **Patch the checker.** Every change under `scripts/` is a numbered patch in `CHECKER-CHANGES.md`: "K-number, what changed, old → new sha256 of each script, which outputs regenerated". The latest is **K22**.
- **CONVENTIONS is frozen between versions.**
  1. Draft any change in `drafts/CONVENTIONS-vX.Y-draft.md`, starting with a one-page summary of the decisions needed.
  2. The owner accepts, and the change is applied as "not frozen".
  3. The owner signs off the applied text, and it is frozen with the commit hash and sha256 recorded (sign-offs B6, B7).

  The owner has given standing permission to *apply* drafted CONVENTIONS and spec changes, but sign-off is the owner's alone.
- **Keep the checksums current.** `SHA256SUMS` lists every committed file except itself; `make check` fails if it is stale. Add new files to it and regenerate after edits. The Python snippet used for this throughout: read the file list, then rewrite `sha256  path` lines.
- **Git.**
  - Commit and push to `claude/new-session-uq6gh3`.
  - Commit messages end with the attribution lines the environment specifies.
  - Do not open pull requests unless asked.
  - Never put model identifiers in commits or files.
- **Sources.**
  - Never invent references or numbers. Fidelity data must cite a source: NIST CCCBDB first (owner decision R3-4), with snapshots saved in `evidence/`.
  - If something is recalled but unsourced, say so in the text.
- **Talking to the owner.** They want a critical peer, with recommendations rather than surveys. Ask only about genuinely ambiguous choices.

## 5. Commands

Setup (once):

```bash
python -m venv .venv
```

```bash
.venv/bin/python -m pip install --require-hashes -r requirements-checker.lock
```

The everyday checks:

```bash
make check PYTHON=.venv/bin/python
```

```bash
node web/tests/web_test.js
```

```bash
make add-molecule PACK=packs/CF4.json PYTHON=.venv/bin/python
```

- `make check` runs the baseline regeneration plus the engine tests; CI runs it before every deploy.
- The browser tests need the network (Pyodide from jsDelivr) and the preinstalled Playwright and Chromium. They are not part of `make check`.
- `make add-molecule` is the gate for a new pack.

Regenerating the committed checks after a deliberate checker or data change (pin the BLAS kernel, K20):

```bash
export OPENBLAS_CORETYPE=Haswell OPENBLAS_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1
```

```bash
.venv/bin/python scripts/generate_groups.py --out . && .venv/bin/python scripts/check_release1.py --out . && .venv/bin/python scripts/build_checks.py --out .
```

Then confirm the diff in `checks/` is what you intended, update `SHA256SUMS`, and run `make check`. Serving locally: `python3 -m http.server` from the repository root, then open `/web/`.

## 8. Things that will bite you

- **Adding an engine module:** add it to the `ENGINE` list in `web/worker.js`. New data directories also go in the worker's `DATA` (or its pack index) and in `web/build_site.sh`, or the site breaks while local tests still pass.
- **CRLF files:** `params/*.csv` use CRLF. Edit them in binary or line-preserving mode, or the diff touches every line.
- **Reference spectra:** the 23 pre-v1.5 entries in `evidence/reference_spectra.json` predate the K20 kernel pin and differ from a fresh run by up to 1.4e−14 eV (they are compared to 1e−9). Append new fixtures; never rewrite old entries.
- **Hard-coded counts in tests:** case counts, quiz counts and rail entries. Packs are excluded from the reference-spectrum loops by design.
- **Views must stay fast.** Every slider move recomputes. Budget: warm view under about 25 ms in CPython, 100 ms on the phone. `schedule_options` is cached on geometry and coupling pattern for this reason. Re-run the D10 speed check (the footer "speed test" button) after anything heavy.
- **Payload keys:** `rule_check` is the L4 rule check; `rules` is the badge table.
- **Pack orientation:** packs give bond lengths and angles, not CCCBDB Cartesians. CCCBDB frames differ from the CONVENTIONS §2 orientation the group files assume (BF3 has a fluorine on +y).
- **The hydrogen factor 0.6** is fitted to orderings inside the window 0.4235–0.6668 (DECISIONS B2). Changing on-sites or adding H constraints means re-deriving that window.
- **Model vs textbook disagreements are recorded, never tuned away.** Examples:
  - B2, C2 and N2 ordering (M1);
  - B2, C2 and Al2 spin;
  - planar CH4's H-only HOMO;
  - counting bond orders of 4/3 for NH3 and 3/2 for H2S and model water, explained in case notes (V5).
- **Network access is limited** to an allow-list. The session environment "thelgos" adds cryst.ehu.es for Bilbao. CCCBDB, LibreTexts and jsDelivr are allowed.
